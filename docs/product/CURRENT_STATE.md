# 当前产品状态

## 本轮竞彩功能目标

在首页现有开奖卡片之后提供“竞彩赛事”栏目，供用户切换查看竞彩足球、竞彩篮球的近期赛事信息与结果。保持原首页导航和彩票数据卡片不变。

## 当前用户路径

首页对每个彩种始终展示最近一次已确认的开奖结果；新一期尚未公布或上游暂时失败时保留上一期，不能把已有奖号清空。本机旧缓存可立即用于首屏，服务端持久快照是跨设备的最终兜底。开奖时段由服务端定时按彩种追查新期号；确认该彩种当天的新期号并保存后，当天停止对该彩种的上游抓取。用户打开页面只读取已保存结果，不触发反复抓取；手动刷新仅重新读取快照。历史与走势图仍按需加载。竞彩栏目与上述开奖同步相互独立。

1. 用户进入首页并滚动至竞彩赛事栏目。
2. 选择足球或篮球，查看来源页面当前公开的竞彩赛事列表，并按实际开赛时间排序。
3. 对未赛/进行中比赛查看开赛时间和状态；有比分/赛果时查看主客队比分。

开奖追新采用 GitHub Actions 每 5 分钟触发 Preview 同步 Worker（北京时间 20:45—23:30）；Worker 通过 GitHub OIDC 校验指定仓库、默认分支和指定工作流，并再次校验时间窗。确认新期开奖后按彩种停止当日抓取。GitHub 定时任务可能有排队延迟。

## 当前模块结构

- 首页开奖卡片：维持现状。
- 竞彩赛事卡：位于开奖卡片之后，使用足球/篮球切换、赛事列表和来源/更新时间提示。
- 全局底部导航、选号、详情和走势图：维持现状。

## 交互和状态

- 默认显示足球和来源公开赛程中的赛事；赛程可能跨北京时间零点，时间旁显示实际月日。
- 类型切换后加载对应运动项目；提供手动刷新。
- 来源页不支持日期参数筛选，因此不提供会产生错误预期的日期选择器。
- 加载、空数据、错误、缓存降级均需明确提示。
- 比赛进行中比分标为即时信息，完赛最终结果以官方赛果发布为准。

## 数据约束

- 使用大象比分公开 HTML 页面作为免密钥数据源：`/scores` 为竞彩足球比分，`/basketball` 为竞彩篮球比分；赛程页分别为 `/preview/football`、`/preview/basketball`。抓取页面当前公布的比赛，不伪装支持日期查询。
- 已实测上述页面服务器端 HTTP 200；来源站 robots.txt 允许公开页面抓取但禁止 `/api/`。只抓公开页面，不请求被禁止路径或绕过访问限制。
- 只接受竞彩专页的竞彩编号记录；只标准化赛事编号、赛事、开赛时间、主客队、状态和比分。赔率字段不写缓存、不下发、不展示。
- 低频请求并缓存标准化结果；失败时保留最近成功缓存及更新时间，若无缓存显示可重试错误。
- 列表接口含赔率字段，但本产品不存储、不转发、不展示这些字段；不提供投注建议。

## 视觉边界

- 沿用现有白色卡片、圆角、灰蓝背景、品牌蓝/红强调和页面间距。
- 不新增导航层级、不改变现有底部导航。
- 优先复用现有 Lucide 图标体系；如本次不需要新增图标，不引入图标资产。
- 移动优先布局，长队名可换行，状态/时间/比分保持清晰。
